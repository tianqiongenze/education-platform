## How to re-run

```bash
# Ensure all services are running on localhost (port-forward or dev launch).
scripts/e2e-full-chain-test.sh

# With a custom run id and report path:
RUN_ID=nightly-$(date +%Y%m%d) \
REPORT_FILE=docs/testing/e2e-nightly-$(date +%Y%m%d).md \
  scripts/e2e-full-chain-test.sh
```

## Safety notes for shared infrastructure

- All test data uses a unique `e2e-test-<RUN_ID>-` prefix (username, studentId,
  sessionId, etc.) to avoid collisions with real data.
- Idempotency keys (`idem-<RUN_ID>-*`) are sent with every mutating request so
  re-runs do not double-create orders, payments, submissions, or grades.
- No destructive `DELETE` calls are issued; the script is safe to run against
  shared/staging environments.
- Duplicate registration on the same `RUN_ID` is treated as a SKIP rather than
  a FAIL.
