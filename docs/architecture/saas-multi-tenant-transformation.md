# 全中台多租户SaaS可抽离改造规划 (D-044)

> 决策编号: D-044 | 日期: 2026-08-05 | 状态: PROPOSED
> 关联: D-042 (AI智能驱动数据中台), D-043 (知识中台SP-07)

---

## 1. 背景与目标

### 1.1 业务背景
本项目群构建的教育平台包含7个共享中台(SP-01~SP-07)，最初设计为自用平台。用户要求所有中台必须具备**可抽离能力**——能随时从教育行业场景中剥离，作为独立SaaS产品服务其他企业。

### 1.2 改造目标
| 目标 | 衡量标准 |
|------|---------|
| 多租户隔离 | 租户间数据零泄露，支持行级/Schema/独立DB三级隔离 |
| 行业无关化 | 剥离教育领域耦合，核心能力通用化 |
| SaaS化运营 | 租户自助开通、配额管理、计量计费 |
| 开放API | 第三方企业通过API Key接入，完整SDK |
| 可独立部署 | 每个中台可独立打包部署，不依赖其他中台 |

```
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐        │
│  │ 租户管理  │  │ 配额管理  │  │ 计量计费  │  │ API网关   │        │
│  │ Tenant   │  │ Quota    │  │ Billing  │  │ Gateway  │        │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘  └────┬─────┘        │
└───────┼─────────────┼─────────────┼─────────────┼───────────────┘
        │             │             │             │
┌───────┴─────────────┴─────────────┴─────────────┴───────────────┐
│                     数据平面 (Data Plane)                          │
│                                                                   │
│  Level 1: 行级隔离 (默认)                                         │
│  ┌─────────────────────────────────────────────────────┐         │
│  │ Shared DB + Shared Schema                            │         │
│  │ 每表加 tenant_id, MyBatis拦截器自动注入              │         │
│  │ 适用: 中小租户(月活<10万)                            │         │
│  └─────────────────────────────────────────────────────┘         │
│                                                                   │
│  Level 2: Schema隔离 (升级)                                       │
│  ┌─────────────────────────────────────────────────────┐         │
│  │ Shared DB, per-tenant Schema                         │         │
│  │ 动态数据源路由, 租户级表结构可定制                    │         │
│  │ 适用: 中大租户(月活10万~100万)                       │         │
│  └─────────────────────────────────────────────────────┘         │
│                                                                   │
│  Level 3: 独立DB (旗舰)                                           │
│  ┌─────────────────────────────────────────────────────┐         │
│  │ per-tenant DB Instance                               │         │
│  │ 物理隔离, 独立备份, 可选独立K8s namespace            │         │
│  │ 适用: 旗舰租户(月活>100万或合规要求)                 │         │
│  └─────────────────────────────────────────────────────┘         │
└───────────────────────────────────────────────────────────────────┘
```

## 5. 技术实现方案

### 5.1 租户上下文传播
```java
// TenantContext.java — 全局租户上下文(ThreadLocal + 虚拟线程兼容)
public class TenantContext {
    private static final ScopedValue<Long> TENANT_ID = ScopedValue.newInstance();
    
    public static Long get() { return TENANT_ID.orElse(null); }
    public static void set(Long id, Runnable task) {
        ScopedValue.where(TENANT_ID, id).run(task);
    }
}
```
> 使用 Java 21 ScopedValue 替代 ThreadLocal(D-039虚拟线程兼容)。

### 5.2 MyBatis多租户拦截器
```java
@Intercepts({
    @Signature(type = Executor.class, method = "query", args = {...}),
    @Signature(type = Executor.class, method = "update", args = {...})
})
public class TenantInterceptor implements Interceptor {
    // 自动在SQL中注入 WHERE tenant_id = ? 条件
    // INSERT自动填充 tenant_id 字段
}
```

### 5.3 动态数据源路由
```java
// 根据租户级别选择数据源: 共享DB → Schema隔离 → 独立DB
public class TenantDataSourceRouter extends AbstractRoutingDataSource {
    @Override
    protected Object determineCurrentLookupKey() {
        Long tenantId = TenantContext.get();
        TenantLevel level = tenantService.getLevel(tenantId);
        return switch (level) {
            case SHARED -> "shared";
            case SCHEMA -> "schema_" + tenantId;
            case DEDICATED -> "dedicated_" + tenantId;
        };
    }
}
```

### 5.4 API网关多租户路由
```
请求 → API Key识别租户 → 注入X-Tenant-Id header → 路由到对应服务
                      ↓ (无效Key)
                   401 Unauthorized
```

### 5.5 计量计费管道
```
API调用 → Pulsar topic: billing.events → Flink聚合(5min窗口)
         → Iceberg billing_summary → 月度账单生成
```

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| SP-03业务中台行业耦合过深 | 改造周期长 | 插件化策略: 核心通用 + 行业插件 |
| 多租户性能损耗 | 查询性能下降 | tenant_id作为分区键, 索引优化 |
| 跨租户数据泄露 | 安全合规风险 | 自动化隔离测试 + 安全扫描 |
| 计量计费精度 | 收入损失 | 双路采集(Pulsar+日志)对账 |
| 租户级配置爆炸 | 运维复杂 | ConfigMap模板 + Kustomize overlay |
