**归属判定准则**(承接 EP-SPEC-001 §2.2)：
- 主体身份是平台/教师/运营/客服 → 全局域
- 主体身份是单用户且高并发读写 → 用户域
- 全平台强一致诉求 → 全局域；单元内强一致即可 → 用户域
- 跨客服调度(TKT)、规则一致性(RSK 规则) → 全局域

## 5. 关键 ADR

### ADR-B01 业务中台能力=共享领域服务，事业群调而非 fork
- **决策**：新 BU 接入 = 调中台 API + 自建本 BU 专属领域(如 IT 后端的代码评测)。
- **中台演进**：通过契约(OpenAPI/Dubbo Triple)+Pact 不破坏消费方；破坏性变更走版本化(v1→v2 并存 ≥2 个版本周期)。
- **依据**：D-001 开放性；避免 4 个 BU 各自 fork 用户/订单导致维护爆炸。
- **后果**：中台接口契约治理成本上升；BU 接入文档与 sandbox 必须齐备。

### ADR-B02 订单/支付强单元化，风控/计费走 Rust 热点
- **决策**：订单事务在 user 单元内闭环(下单+锁券+扣库存本地事务)；计费/风控高频规则用 Rust 保证 P95。
- **依据**：D-009(语言栈)/D-012(混合单元化)。
- **后果**：Rust 服务需独立 CI(交叉编译 aarch64/x86_64)；Java 与 Rust 通过 gRPC 交互；Rust 团队经验需培养。

### ADR-B03(新增) 营销券模板全局单写，个人券单元化
- **决策**：券模板/活动在全局域主库单写(写少读多)；用户领券/用券落 user 单元(高并发)。
- **依据**：D-012 + EP-SPEC-001 §2.2 Ops/Account 上下文边界。
- **后果**：领券防超发需 Redis Lua 原子扣预算 + 单元落库补偿；超发由对账任务兜底。

### ADR-B04(新增) 通知事件驱动 + 模板 FGAC
- **决策**：NTF 全事件驱动(Pulsar)，模板版本化 + JWT 驱动 FGAC 隔离租户。
- **依据**：D-006(状态外化)/D-019(多租户 FGAC)。
- **后果**：上游事件 schema 治理(Pulsar Schema Registry)；模板变更需 Pact 契约测试。

### ADR-B05(新增) 风控规则热更新不重启
- **决策**：规则存 Nacos，Rust RuleEngine 监听变更热加载；5s 内全节点生效。
- **依据**：NFR-P05 + 运维诉求。
- **后果**：规则版本化 + 回滚机制必须齐备；规则变更审计。

## 7. Rust 热点服务架构

### 7.1 计费引擎 BillingEngine(OPM)

```
┌──────────────── BillingEngine(Rust, gRPC)─────────────────┐
│  入口: tonic gRPC /billing.compute                        │
│  ├─ 输入: order_items + coupons + user_level              │
│  ├─ 价计算: 原价→券抵扣→会员折扣→积分抵扣(纯函数)          │
│  ├─ 分账: BU 分成 / 教师分成 / 平台留存                    │

```
