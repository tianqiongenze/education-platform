# ADR-A05: 多级智能记忆系统 L0~L3

> 关联：D-045 多级智能记忆系统；铁律 8（决策对比分析）；SP-04 AI 中台 ep-memory 子系统；ADR-A06 Mem0 框架集成；ADR-A02 多租户 FGAC；D-033 缓存铁律。

## 1. 问题陈述与约束条件

教育平台 3 亿用户、100 万并发，AI 智能体（D-046）在会话过程中需要持久化的上下文与跨会话的长期记忆。现状（D-048 审计 P0-5）显示 `ep_memory` 模块绕过 Mem0 用手写 stub 实现，既无分级策略也无遗忘机制，导致：

- 上下文随对话窗口增长爆涨，token 成本失控；
- 跨会话/跨设备续聊无记忆延续，用户体验割裂；
- 个体长期记忆与组织级共享知识无分层，权限边界模糊。

约束条件：

1. **多租户隔离**：记忆数据按 tenant_id 单点注入（ADR-A02），L3 组织记忆跨用户共享需显式授权。
2. **规模天花板**：3 亿用户 × 千级租户，L2 长期记忆向量检索需支持 10 亿级（ADR-INF-01 Milvus 已选）。
3. **铁律 7（D-033）**：热路径记忆走 Redis Cluster，冷路径走 Milvus/TiDB/Neo4j。
4. **铁律 8**：记忆框架必须三方对比后定论（见 ADR-A06）。
5. **D-040 GraalVM**：Python 侧（SP-04）不涉及 AOT；Java SDK 侧不内嵌存储引擎，AOT 无障碍。
6. **可观测**：记忆生命周期事件需审计落湖（Iceberg）。

## 2. 四级记忆架构

```
┌─────────────────────────────────────────────────────────────────┐
│                    MemoryManager (编排层)                        │
│   recall(user, query) → [L0] → [L1] → [L2] → [L3]  分级召回     │
│   remember(user, turn) → L0 写入 → 异步 L1 摘要 → L2 提取        │
└─────────────────────────────────────────────────────────────────┘
   │              │              │                  │
   ▼              ▼              ▼                  ▼
┌─────────┐  ┌─────────┐  ┌──────────────┐  ┌────────────┐
│ L0 即时 │  │ L1 工作 │  │ L2 长期记忆   │  │ L3 组织记忆│
│ Redis   │  │ Redis   │  │ Milvus+TiDB  │  │ Milvus     │
│ 10 轮   │  │ 摘要    │  │ +Neo4j       │  │ +Neo4j     │
│ TTL 24h │  │ TTL 7d  │  │ Mem0 pipeline│  │ 租户级共享 │
└─────────┘  └─────────┘  └──────────────┘  └────────────┘
   │ 降级         │ 降级         │ 降权/归档        │ 永不自动过期
   ▼              ▼              ▼                  ▼
  24h 淘汰      7d → L2       30d 降权 / 90d 归档   仅手动治理
```

| 级别 | 定位 | 存储 | 窗口/TTL | 写入触发 | 召回时机 |
|------|------|------|---------|---------|---------|
| **L0 即时记忆** | 当前会话最近对话轮次 | Redis Cluster | 最近 10 轮，TTL 24h | 每轮对话结束 | 每次召回优先（最热） |
| **L1 工作记忆** | 会话摘要 + 任务上下文 | Redis Cluster | TTL 7d | 会话切换/摘要触发 | L0 未命中或需跨会话 |
| **L2 长期记忆** | 情景/语义/程序三类 | Milvus + TiDB + Neo4j | 30d 降权 / 90d 归档 | Mem0 pipeline 异步提取 | L1 未命中或语义检索 |
| **L3 组织记忆** | 租户级知识沉淀 | Milvus + Neo4j | 永不自动过期 | 治理流程手动晋升 | 显式授权后跨用户共享 |

### 2.1 L2 三类长期记忆

| 子类 | 存储后端 | 内容 | 召回方式 |
|------|---------|------|---------|
| 情景记忆 (episodic) | Milvus `mem_episodic` | 用户过往对话片段向量化 | 向量相似度 top-k |
| 语义记忆 (semantic) | TiDB `mem_semantic` | 结构化事实（偏好/属性/已确认信息） | SQL 精确查询 |
| 程序记忆 (procedural) | Neo4j `mem_procedural` | 实体-关系图谱（用户-课程-技能-目标） | Cypher 图遍历 |

## 3. 候选方案

| # | 方案 | 一句话定位 |
|---|------|-----------|
| A | **L0~L3 四级分级 + Mem0 核心 + 自研 L0/L1/L3**（已选） | 分级生命周期管理，Mem0 负责 L2 提取/召回，自研 L0/L1 Redis 层与 L3 治理层 |
| B | **单级长期记忆（仅 Milvus + TTL）** | 所有记忆统一存 Milvus，靠 TTL 区分新旧，无工作/组织分层 |
| C | **全自研四级记忆（不引 Mem0）** | L0~L3 全部自研，提取/召回/去重/冲突消解自行实现 |

## 4. 对比维度表

| 维度 | 方案 A（四级+Mem0） | 方案 B（单级+TTL） | 方案 C（全自研四级） |
|------|---------------------|--------------------|----------------------|
| **上下文成本控制** | L0 10 轮窗口 + L1 摘要压缩，token 成本可控 | 无窗口管理，上下文持续膨胀 | 与 A 等价 |
| **跨会话续聊** | L1 摘要 + L2 情景双保险 | 仅靠 Milvus 向量召回，摘要缺失 | 与 A 等价 |
| **组织级共享** | L3 独立层 + 显式授权治理 | 无组织级概念，权限边界模糊 | 与 A 等价 |
| **开发成本** | Mem0 提供 L2 提取/去重/冲突消解，自研聚焦 L0/L1/L3 | 最低，但能力残缺 | 最高，重复造轮子（违反铁律 8） |
| **社区支持** | Mem0 社区活跃，Milvus/TiDB/Neo4j 后端可定制 | 仅 Milvus 社区 | 无社区支持 |
| **3 亿用户扩展性** | Redis Cluster + Milvus 分片 + TiDB 分布式，可水平扩展 | Milvus 单集群压力大 | 与 A 等价 |
| **多租户隔离** | Redis key 前缀 + Milvus partition_key + TiDB tenant_id + Neo4j 租户标签 | 仅 Milvus partition_key | 与 A 等价 |

## 5. 结论与理由

**采纳方案 A：L0~L3 四级分级 + Mem0 核心 + 自研 L0/L1/L3**。

理由：

1. **分级生命周期匹配教育场景**：即时对话（L0）、会话任务（L1）、个体长期（L2）、组织知识（L3）四个粒度天然对应"当前答疑—本次作业—学生画像—学校知识库"的语义层次，单级方案无法表达。
2. **Mem0 复用社区成果**：L2 提取/去重/冲突消解是成熟问题，Mem0 已实现并支持 Milvus/TiDB/Neo4j 后端，自研属重复造轮子（违反铁律 8）；L0/L1/L3 场景特化强，自研更灵活。
3. **成本可控**：L0 10 轮窗口 + L1 摘要压缩将热路径 token 成本压到最低，L2 异步提取不阻塞主链路。
4. **与现有栈对齐**：Redis Cluster（D-033）、Milvus（ADR-INF-01）、Neo4j（ADR-INF-02）、TiDB 均为已选组件，无新增基础设施负担。
5. **L3 治理可控**：组织记忆永不自动过期，需治理流程手动晋升，避免错误信息在租户内扩散。

## 6. 遗忘机制

| 级别 | 遗忘策略 | 触发条件 | 实现 |
|------|---------|---------|------|
| L0 | TTL 淘汰 | 24h 未更新 | Redis EXPIRE |
| L1 | 降级到 L2 | TTL 7d 到期 | 后台 job 提取摘要写入 L2 后删除 |
| L2 | 降权 → 归档 | 30d 降权（召回分数 ×0.5）/ 90d 归档（移至冷存） | Milvus 标记 + TiDB 状态字段 + Neo4j 边权重衰减 |
| L3 | 不自动遗忘 | 仅手动治理 | 管理员 API 显式删除 |

## 7. 风险与对策

| 风险 | 对策 |
|------|------|
| Mem0 社区版功能有限，3 亿用户需二次开发 | 自研 L0/L1/L3 规避核心瓶颈；Mem0 仅负责 L2 提取，可替换 |
| L1 摘要质量不稳定 | 摘要 prompt 走 Reflexion 评估（D-046），阈值 0.7；失败兜底保留原文 |
| L2 向量召回噪声 | 召回 top-k 后经 MemoryManager 重排序（RRF 融合情景/语义/程序三路） |
| L3 组织记忆污染 | 晋升需双人审核 + 审计留痕；错误信息可回滚 |
| Redis Cluster 故障致 L0/L1 不可用 | 降级到 MemorySaver（D-046 已有），L2 直接兜底召回 |

## 8. 与现有系统的关系

- **D-046 智能体架构**：MemoryManager 作为 LangGraph 节点的工具注入，`recall`/`remember` 在每轮对话前后调用。
- **D-033 缓存铁律**：L0/L1 即 ep-memory 的缓存层，遵循 Redis Cluster + 本地兜底铁律。
- **ADR-A02 多租户**：所有记忆键含 tenant_id 段，L3 跨用户共享需显式授权。
- **ADR-INF-01/02**：Milvus/Neo4j 已选型，ep-memory 直接复用 collection/graph。
- **D-048 审计 P0-5**：本 ADR 解决 `ep_memory` 手写 stub 问题，接入 Mem0。

---

**文档结束**。本 ADR 确立 L0~L3 四级记忆架构，满足铁律 8 三方对比要求，关联 ADR-A06（Mem0 集成细节）。
