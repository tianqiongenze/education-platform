## 1. 引言

### 1.1 目的与范围
本文档定义 education-platform 项目群中 **SP-07 知识中台** 子项目的功能、非功能需求与验收标准，作为后续 SAD/SDD/测试/部署文档的上游输入。SP-07 面向技术开发团队、其他员工、客服、授课教师、学员五类用户群体，提供企业级 AI 知识库、智能检索、Agent 编排、知识共创与多租户 SaaS 抽离能力。

**范围**：
- 包含：知识库管理（多格式解析/分块/向量化/版本/知识图谱）、智能检索（混合检索/RAG 问答/推荐/联合检索）、Agent 管理（创建/编排/会话/工具扩展）、知识共创（社区/评审/积分）、多租户 SaaS（隔离/配额/开放 API）、学习路径（AI 推荐/进度/评估）。
- 不包含：LLM/Embedding 模型本体训练（属 SP-04 AI 中台）、底层向量数据库运维（属基础设施层）、业务中台课程订单领域数据（属 SP-03）。

### 1.2 文档约定
- 编号规则：`FR-KB-<序号>`（KB = Knowledge Base），优先级 P0/P1/P2。
- 中文为主，技术术语保留英文（如 Chunking、RRF、RAG、Function Calling）。
- 需求描述采用「ID | 需求 | 优先级 | 描述」表格结构，与 SP-02/SP-04 SRS 风格一致。
- 验收标准与需求追溯矩阵双向链接，变更需同步更新。

## 2. 总体描述

### 2.1 产品愿景
构建**企业级 AI 知识中台**，统一沉淀五类用户群体的显性与隐性知识，通过 RAG + Agent + 知识图谱实现"问得到、答得准、学得会"。中台必须设计为**可抽离的 SaaS 多租户架构**，能以独立产品形态服务其他企业，单实例支撑多租户隔离、自定义品牌与配额计费。

### 2.2 用户群体

| 用户群体 | 角色描述 | 核心诉求 | 使用场景 |
|---------|---------|---------|---------|
| 技术开发团队 | 后端/前端/算法工程师、SRE | 技术文档、API 文档、代码知识库、故障排查知识快速检索 | 排障时 RAG 问答定位根因；编码时检索 API 用法；新人 onboarding |
| 其他员工 | HR/财务/行政/法务等非技术岗 | 公司制度、HR 政策、操作手册、内部 FAQ 自助查询 | 入职流程查询、报销制度问答、办公系统操作指引 |
| 客服 | 一线客服、客服主管 | 产品知识库、常见问题、话术库、工单知识即时获取 | 工单处理中调用 Agent 生成回复；话术库检索；新客诉根因复盘 |
| 授课教师 | 讲师、教研、助教 | 课程素材、教学资源、题库、教学经验沉淀与复用 | 备课检索素材；组卷调用题库；课后沉淀教学经验 |
| 学员用户 | 在线学习学员 | 学习资料、课程笔记、问答社区、个性化学习路径 | 学习中 RAG 答疑；社区提问互动；AI 推荐学习路径 |

### 2.3 运行环境
- 后端：Spring Boot 4.0.7 + Spring Cloud 2025.1.2 + SCA 2025.1.0.0 + Dubbo 3.3.6，Java 21 虚拟线程（D-039），GraalVM Native Image（D-040）。
- 前端：pnpm + Turborepo + Taro4 + TanStack Query + Vite + Zod + AntD。
- 数据存储：Milvus/Qdrant（向量）、TiDB（结构化元数据）、Redis Cluster（缓存/会话，D-033）、S3/MinIO（原始文档）、Neo4j/NebulaGraph（知识图谱）。
- 部署：K8s 多区域多活（D-041），国内异地双活 + 海外独立集群。

### 2.4 约束与假设

| ID | 约束 | 来源 |
|----|------|------|
| C-01 | 复用 SP-04 AI 中台的 LLM/Embedding/Agent 能力，不自建模型栈 | D-042 |
| C-02 | 多租户隔离 = namespace + pool + JWT 驱动 FGAC，禁止 app 层拼接 tenant_id | D-019 / ADR-A02 |
| C-03 | 跨租户数据泄漏事故 = 0（#1 事故类防控） | ADR-A02 |
| C-04 | Java 服务启用虚拟线程，关键服务编译 GraalVM Native Image | D-039 / D-040 |
| C-05 | 国内异地多活 + 海外独立，知识中台按区域部署独立实例 | D-041 / D-004 |

### 2.5 依赖
- **SP-04 AI 中台**：提供 LLM 路由/缓存/限流、Embedding 向量化、LangGraph Agent 编排、Function Calling 框架。
- **SP-01 技术中台**：提供 Pulsar 消息、可观测、K8s、Redis Cluster。
- **SP-02 数据中台**：提供用户行为特征（用于知识推荐与学习路径）。
- **SP-03 业务中台**：提供课程/订单/用户领域数据（学员学习路径场景）。

## 3. 功能需求

> 编号规则：`FR-KB-<序号>`。域=知识库管理/智能检索/Agent管理/知识共创/多租户SaaS/学习路径。

### 3.1 知识库管理

| ID | 需求 | 优先级 | 描述 |
|----|------|--------|------|
| FR-KB-01 | 多格式文档上传 | P0 | 支持 PDF/Word/Markdown/Excel/PPT/HTML 上传，单文件 ≤100MB，支持批量上传、拖拽、API 推送；原文存 S3/MinIO |

| FR-KB-04 | 知识分类体系 | P0 | 多级目录 + 多标签，支持租户自定义 Taxonomy；支持分类导入导出 |
| FR-KB-05 | 文档版本管理 | P1 | 文档更新生成新版本，支持版本对比（diff）、回滚、版本历史审计 |
| FR-KB-06 | 知识图谱构建 | P1 | 调用 SP-04 LLM 进行实体抽取、关系抽取，存 Neo4j/NebulaGraph；支持图谱可视化、图查询 |

### 3.2 智能检索

| ID | 需求 | 优先级 | 描述 |

### 3.7 MCP 协议合规

> 2026-08-05 追加。对应决策 D-047 与 ADR-A07：SP-07 MCP Server 采用官方 MCP Java SDK + Spring AI MCP 注解实现。

| ID | 需求 | 优先级 | 描述 |
|----|------|--------|------|
| FR-MCP-04 | MCP 协议合规 | P0 | SP-07 MCP Server **MUST** 通过官方 MCP conformance tests（40/40）；**SHALL** 使用 Streamable HTTP 传输（MCP 2.0 spec）；**SHALL** 支持协议版本协商（`MCP-Protocol-Version` header，向下兼容 1.0 initialize 握手）；所有工具 **SHALL** 通过 `@McpTool` 注解注册，禁止手写 JSON-RPC dispatcher 与手写工具注册表 |

**验收条件**：
- 在 CI 中执行官方 MCP conformance test 套件，结果为 40/40 通过。
- `POST /mcp/v1` 端点响应 `MCP-Protocol-Version` header，能正确完成 initialize → negotiate → tool call 流程。
- 客户端发送 `notifications/cancelled` 时，服务端取消对应工具执行的虚拟线程（对齐 D-039）。
- 代码库中不存在 `McpController` / `McpRequest` / `McpResponse` / `ToolSchema` / `ToolRegistry` 手写类。
- 所有暴露工具均带 `@McpTool` 注解，参数带 `@McpToolParam` 注解。

## 5. 用户故事

### 5.1 技术开发团队
- US-DEV-01：作为后端工程师，我希望通过 RAG 问答检索 API 文档与故障排查知识并引用溯源，以便排障时 1 分钟内定位根因。
- US-DEV-02：作为前端工程师，我希望代码知识库支持代码块高亮与语义搜索，以便快速复用团队组件。
- US-DEV-03：作为 SRE，我希望 Agent 能绑定工单知识库 + Prometheus 工具自动生成故障复盘，以便 MTTR 从 30min 降至 10min。

### 5.2 其他员工
- US-STAFF-01：作为新员工，我希望自然语言提问"年假怎么请"，系统返回 HR 政策原文与流程，以便无需找人。
- US-STAFF-02：作为财务，我希望报销操作手册支持多轮追问，以便复杂场景逐步指引。
- US-STAFF-03：作为行政，我希望内部 FAQ 由 AI 自动汇总高频问题，以便减少重复咨询。

### 5.3 客服
- US-CS-01：作为一线客服，我希望工单处理时 Agent 即时生成回复建议（绑定产品知识库 + 话术库），以便首响时间 <30s。
- US-CS-02：作为客服主管，我希望新客诉能匹配历史相似工单知识，以便快速定级与转派。
- US-CS-03：作为客服，我希望话术库支持按场景检索并 AI 优化语气，以便提升满意度。

### 5.4 授课教师
- US-TEACHER-01：作为讲师，我希望备课时跨课程素材库联合检索，以便 10 分钟内组装课件。
- US-TEACHER-02：作为教研，我希望题库支持按知识点 + 难度 AI 组卷，以便快速产出测验。
- US-TEACHER-03：作为助教，我希望课后教学经验能沉淀评审后入知识库，以便团队复用。

### 5.5 学员用户
- US-STU-01：作为学员，我希望学习中 RAG 答疑引用课程笔记与教材，以便即问即答不中断学习。
- US-STU-02：作为学员，我希望 AI 生成个性化学习路径并动态调整，以便高效达成学习目标。
- US-STU-03：作为学员，我希望在问答社区提问并获得 AI 候选答案 + 学员回答，以便快速解惑。

|--------|------|------|
| 搜索延迟 | 语义搜索 P95<500ms（压测环境实测） | NFR-01 |
| 问答延迟 | RAG 问答 P95<3s | NFR-02 |
| 并发 | 10 万在线 + 1 万并发问答压测通过 | NFR-04/05 |
| 可用性 | 多区域多活故障注入，可用性 ≥99.95% | NFR-06 |
| 安全 | 第三方渗透测试跨租户泄漏 = 0；RBAC+ABAC 全覆盖 | NFR-07/08 |

### 6.3 场景验收
- 场景 A：技术开发团队上传 50MB PDF 技术文档，30s 内完成解析索引，RAG 问答引用溯源准确。
- 场景 B：客服 Agent 绑定产品知识库 + 话术库，工单进入后 30s 内生成回复建议。
- 场景 C：租户 A 用户发起查询，租户 B 数据零泄漏（渗透测试验证）。
- 场景 D：学员学习路径由 AI 生成，掌握度评估后路径自动调整。
