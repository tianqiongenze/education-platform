## 1. 执行摘要

本报告汇总了教育平台在 2026-08-08 执行的全链路压力测试结果，覆盖 **10,000 / 100,000 / 1,000,000 并发** 三个量级，以及 **Java / Python / Go / Rust (理论)** 四语言框架开销基准对比。测试旨在评估系统在极端并发下的承载能力、瓶颈边界及语言选型合理性。

### 1.1 核心发现

1. **TiKV 单节点是系统硬瓶颈**：实际 RPS 从 10K 级的 220 仅增长到 1M 级的 587（2.7x），远未达到设计目标的 10x~100x 增长。所有依赖 DB 的服务在并发压力下崩溃。
2. **语言选型整体正确**：Go 网关层在 1M 级别仍保持 52% 可用率且 P95 仅 2.33s；Python AI 层在 mock 模式下 10K/100K 完美；Java 业务层崩溃的根因是 TiKV 而非语言本身。
3. **共享基础设施安全**：TiKV 重启次数在整个测试周期内保持在 8 次，无新增重启，共享 K8s 集群未被压测击穿。
4. **非 DB 服务后崩溃**：AI/Go 服务在 10K/100K 完美运行，仅在 1M 级别才开始退化，验证了 DB 解耦的架构价值。

## 9. 瓶颈分析

### 9.1 根因：TiKV 单节点读队列饱和

共享 K8s 集群的 TiKV 仅有 1 个节点（tikv-aws-8495698b6c-47xlr），在 5M 行数据的读压力下：

- **读队列满**：新查询被拒绝
- **查询超时**：60s deadline exceeded
- **连接池泄漏**：HikariCP 200 连接池被超时查询占满

### 9.2 级联效应链

```
TiKV 读队列满
    ↓
sp03/sp05 DB 查询超时 (60s deadline)
    ↓
HikariCP 连接池耗尽 (200 连接被占满)
    ↓
Dubbo RPC 超时 (10s)
    ↓
BFF HTTP 超时 (15s)
    ↓
k6 标记为错误
```

### 9.3 DB 依赖 vs 非 DB 服务行为对比

| 服务类型 | 10K | 100K | 1M | 行为特征 |
|----------|------|------|-----|----------|
| **DB 依赖 (Java BFF/sp03/sp05)** | 72-100% 错误 | 78-100% 错误 | 100% 错误 | 首先崩溃，TiKV 瓶颈直接传导 |
| **Redis 缓存路径 (评分查询)** | 0% 错误 | 0% 错误 | 0% 错误 | 全程稳定，缓存有效隔离 DB 压力 |
| **无 DB (Python AI, mock)** | 0% 错误 | 0% 错误 | 93% 错误 | 10K/100K 完美，1M 工作线程耗尽 |
| **无 DB (Go gateway)** | 0% 错误 | 0% 错误 | 52% 错误 | 10K/100K 完美，1M 开始退化但 P95 最低 |

### 9.4 RPS 增长瓶颈分析

| 并发级别 | 设计 RPS 目标 | 实际 RPS | 达成率 | 瓶颈点 |
|----------|-------------|----------|--------|--------|
| 10K | 1,000 | 220 | 22% | TiKV 读队列饱和 |
| 100K | 3,000 | 430 | 14% | TiKV + HikariCP 耗尽 |
| 1M | 5,000 | 587 | 12% | 全链路级联崩溃 |

RPS 从 220→587 仅增长 2.7x，远未达到 10x~100x 目标。TiKV 单节点构成不可逾越的硬瓶颈。

## 12. 结论

### 12.1 总体评估

本次全链路压测（10K + 100K + 1M + 跨语言基准）全面验证了教育平台在极端并发下的系统行为，核心结论如下：

1. **系统最大承载能力约 220 RPS**（10K 级别），超出后 DB 依赖服务开始崩溃，1M 级别下连无 DB 服务也开始退化。
2. **TiKV 单节点是不可逾越的硬瓶颈**，RPS 从 220→587 仅增长 2.7x，远未达到设计目标。生产环境必须横向扩展至至少 3 节点并启用读写分离。
3. **语言选型整体正确**：Go 网关最优（1M 级 52% 可用，P95=2.33s），Python AI 层次之（10K/100K 完美），Java 业务层崩溃根因是 TiKV 而非语言本身。
4. **Redis 缓存路径全程稳健**（评分查询 0% 错误），验证了多级缓存架构的价值。
5. **共享基础设施安全**，TiKV 重启次数全程保持 8 次，无新增重启，压测未击穿共享 K8s 集群。

### 12.2 性能排名总结

**纯框架开销**：
```
Rust (理论) > Go >> Python > Java
  0.4ms      1.55ms   1.92ms    63.4ms
  (4x)       (1x)     (1.2x)    (41x)
```

**高并发抗压**：
```
Go ≈ Rust (理论) > Python >> Java
52% 可用      ~80%      7%       0%   (1M 级别)
```
